# Java 26.3 terrain implementation and evidence

The live `terrain` generator still uses this project's existing algorithm. `src/World/Vanilla` is a native port of the official 26.3 Overworld chunk pipeline up to carvers (see [Vanilla Overworld terrain](#vanilla-overworld-terrain)). It is not yet connected to chunk generation and does not change existing saves. The scalar classes in `src/World/Generation` remain the verified random and noise primitives it builds on.

`tools/update_reference.py` exports `reference/26.3/worldgen-noise.json` by invoking the actual classes in the checksum-pinned official server JAR. Run with Python 3.11+ and a HotSpot Java 25 JDK (`JAVA_HOME=/path/to/jdk python3 tools/update_reference.py`). The reference tool needs the HotSpot diagnostic `_dlog` intrinsic switch described below. PHP needs no Java process, FFI or Java extension to run these classes.

The PHP checks run in `php tests/worldgen-noise.php` and in both the unit and full suites. They compare raw IEEE float/double bits or exact integer outputs, including:

- Signed 64-bit wrapping arithmetic, the legacy 48-bit LCG, xoroshiro128++ and seed upgrading. Products use integer limbs to avoid PHP's conversion to floating point on overflow.
- Bounded random rejection, interleaved uniform samples, Gaussian caching, forked streams, coordinate seeds, UTF-16 string hashes, named MD5 positional seeds and reseeding. Seeds include signed 64-bit extrema and negative values.
- Java 26.3 scalar Perlin sampling and float32 interpolation, with random consumption taken from the official implementation. Samples include negative coordinates, world edges and coordinate wrapping boundaries.
- Modern NormalNoise scalar 2D/3D sampling for all 64 built-in noise definitions, plus sparse/zero amplitudes, all normalization modes and octave/amplitude limits. Each definition is tested with both random sources and three seeds. Additional fixtures check the official parameter codec's range rules and optional null defaults.

Gaussian samples deserve a specific qualification: the default JVM's `Math.log` intrinsic and the same pinned Java code with only that intrinsic disabled yield different final bits for some samples. The exporter records both real observations. PHP uses the permitted fdlibm logarithm in `StableMath` and matches the disabled-intrinsic observations exactly; its difference from the default observations must stay within two double ULPs. The checked-in fixtures currently contain 17 such differences. This is not a claim of bit-identical Gaussian output on every JVM. Every other exported field must match across both JVM runs; the exporter fails otherwise. See `NOTICE.md` for the fdlibm notice.

Still required for terrain parity: the full biome selection, aquifers, material/surface rules, carvers, features and structures, Nether and End generation, and comparison of actual generated chunks against Java. Legacy Nether biome sampling and derivative/bulk noise APIs are not implemented by these scalar classes. Existing seed-range settings and world storage also require a separately tested migration before exposing vanilla generation. Issues #25, #41, #46, #47 and #49 remain open.

## Density graphs

`DensityGraph` loads the 55 built-in density-function definitions exported through the pinned server's registry codecs. `worldgen-density.json` records the actual official RandomState scalar output for every definition with Overworld random settings, three signed world seeds and 43 coordinates: interpolation/chunk boundaries, negative coordinates, far world positions and End inner/outer island boundaries. `php tests/worldgen-density.php` checks exact float bits in both forward and reversed request order. There are no skipped definitions or numeric tolerances in these comparisons.

Implemented graph operations include named positional noise, shifts, gradients, arithmetic, selection, clamps, nested cubic splines, slicing, interpolation, preliminary surface search, legacy smeared/blended noise and the End's zero-offset simplex island sampler. Cache storage is confined to one sample request. The tests also reject missing and cyclic references and verify failed compilation does not poison a subsequent valid request. The Perlin interpolation core is shared with the vertical-smear sampler and remains covered by the original noise fixtures.

This scalar graph currently assumes a new, unblended world with no structure beard contribution. All graph samples use the official Overworld random settings; Nether legacy biome samplers and dimension-specific complete router/resource settings still need their own comparisons. The class accepts trusted decoded reference definitions, not arbitrary external data packs, and only implements the operation forms used by the built-in graph fixture. It is not wired into production chunk generation. Matching scalar density samples does not prove volume execution, biome selection, materials, aquifers, structures or matching complete generated chunks.

## Vanilla Overworld terrain

`PhpMinecraftJavaServer\World\Vanilla\OverworldGenerator` reproduces the official 26.3 Overworld chunk stages before decoration, reading the official worldgen registries copied from the pinned JAR into `reference/26.3/worldgen` (density functions, noises, noise settings, material rules and conditions, carvers and biomes).

- **Density volumes.** 26.3 fills a chunk through volume samplers whose arithmetic differs from single samples: Perlin octaves add the gradient terms in another order, stack frequencies and amplitudes multiply first, and interpolation advances along Y by repeated float addition. `RandomState` compiles the official definitions as `DensityFunctionCompiler` does. References are inlined, caches with equal inputs share one cache, and parts that do not vary along an axis are sliced at that axis's coordinate 0. A single-value request inside a cached volume returns the volume's value, as `SamplerContext` does, so the stages sample in vanilla's order.
- **Aquifers.** `Aquifer` ports `NoiseBasedAquifer`: jittered fluid cells, preliminary surface sampling, floodedness, spread, lava and barriers.
- **Biomes.** `BiomeSource` searches the official multi-noise parameter list (`reference/26.3/worldgen/biome-parameters.json`, exported by `tools/ExportBiomeParameters.java` with exact quantized values) through a port of `Climate.RTree`. Chunks are filled in vanilla's section/x/y/z order, because the previous result settles exact ties. Carvers use the uncached single-sample resolver, as vanilla does.
- **Material rules.** `MaterialSystem` ports `MaterialSystem` and `MaterialRuleContext`: lazy conditions, surface depth and secondary noise, biome pruning by the 3×3 chunk palette, vertical gradients (bedrock and deepslate), copper and iron ore veins, terracotta bands, eroded badlands pillars and frozen-ocean icebergs. Biome temperature follows `Biome.getTemperature` with its frozen modifier. `BiomeClimate` also ports `BiomeManager`'s zoomed lookup.
- **Carvers.** `Carvers` ports the cave and canyon carvers, the carving mask and its application through the aquifer, including the top material for exposed dirt.

`tools/ExportWorldgenChunks.java` generates chunks offline with the official `NoiseBasedChunkGenerator` and records biomes and the block states after the noise, surface and carver stages. With `-Ddensity=true` or `-Dclimate=true` it adds the raw final-density or climate buffers. `tools/worldgen_fixture.py` reduces the output to per-stage hashes in `reference/26.3/worldgen-chunks.json`. `php tests/vanilla-worldgen-unit.php` checks 11 chunks of two seeds at every stage, including a negative 64-bit seed, mountain biome ties, eroded badlands, sulfur caves, mangrove swamps and chunks 30 million blocks out.

During development, every block of 47 seed-42 chunks matched vanilla through carvers, one chunk per Overworld surface biome plus far coordinates. The density and climate buffers matched bit for bit as well. Each chunk takes about 2–3 seconds in PHP without JIT and about half that with opcache JIT.

Not done yet: structures and their terrain adaptation (beardifier), blending with old chunks, and every decoration step (features: trees, ores, vegetation, lakes, springs and the rest). `tools/ExportFeatureOrder.java` records the global placed-feature order per step that will seed feature placement. Nether and End noise generation are also still to be ported.
