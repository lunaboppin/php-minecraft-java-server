# PHP Minecraft Java Server — vanilla parity roadmap

The target is **1:1 feature and observable behavior parity with the official Minecraft Java 26.3 server**: protocol **777**, data version **5023**. The game runtime remains native PHP. This is a long-term target, **not a statement that the current experimental server has reached parity**.

Tracking issue: [#1](https://github.com/lunaboppin/php-minecraft-java-server/issues/1). [All parity issues](https://github.com/lunaboppin/php-minecraft-java-server/issues?q=is%3Aissue+label%3Aparity). [Milestones](https://github.com/lunaboppin/php-minecraft-java-server/milestones).

The initial backlog contains **55 implementation/cleanup issues and one tracking issue**, grouped into four milestones. GitHub is the source of truth for current issue status; this document is an index. Add newly discovered gaps instead of treating this list as an exemption from missing behavior.

## Reference and definition of done

Use the checksum-pinned official distribution in `reference/26.3/version.json` (server SHA-1 `33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`) and its data/registries. Java is reference/test tooling. Keep the PHP security baseline enforced.

A feature is complete when reproducible differential scenarios show matching behavior, its relevant packets/state decode correctly, and affected multiplayer/chunk/dimension/restart paths are covered. Packet decoding alone does not prove gameplay parity. Exact world generation means matching the official seed-specific result, not visually similar custom noise. Existing SQLite/custom-terrain saves need explicit tested migrations. Any proposed permanent deviation needs agreement and documentation; do not silently call an approximation parity.

## First work

- [#56](https://github.com/lunaboppin/php-minecraft-java-server/issues/56): standardize the project identity and internal identifiers as **PHP Minecraft Java Server**.
- [#2](https://github.com/lunaboppin/php-minecraft-java-server/issues/2): establish the shared vanilla-versus-PHP differential harness.
- [#3](https://github.com/lunaboppin/php-minecraft-java-server/issues/3): audit packet/state coverage and close required protocol gaps.
- [#4](https://github.com/lunaboppin/php-minecraft-java-server/issues/4), [#7](https://github.com/lunaboppin/php-minecraft-java-server/issues/7), [#8](https://github.com/lunaboppin/php-minecraft-java-server/issues/8): establish ticks, durable state ownership and chunk lifecycles before building dependent simulations.

Dependencies define implementation order; milestone numbering groups work and is not a delivery-date promise. P0 marks correctness/compatibility foundations, P1 marks core behavior/integration, and P2 marks advanced systems after their prerequisites. Existing tests, source data and saves must remain valid while a feature is developed.
