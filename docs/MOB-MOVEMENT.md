# Mob movement reference and integration

The native movement work is tracked in #86, with damage/knockback in #87 and shared collision/navigation in #21/#35. The modules in this change establish verified movement arithmetic and a replayable world test. **The production mob coordinator still uses its previous movement loop.** Live knockback, packet delivery, controllers, goals, fluids and species-specific travel remain to be integrated and verified.

`World/EntityPhysics.php` contains shared float/double arithmetic, knockback and input rotation. `World/AirTravel.php` integrates one ordinary ground/air tick against actual World block state. `World/Collision.php` separates static voxel clipping and candidate-height stepping. `Protocol/LowPrecisionVector.php` implements the protocol-777 LpVec3 format used by entity motion; it is not the older three-short velocity format. Keeping these responsibilities separate lets controllers and network tracking use the same verified physics later.

The pinned Java 26.3 server JAR supplies:

- 581 low-precision vector boundary/random cases, including full motion packet bytes, decoded doubles, saturation, NaN and infinities.
- 1,440 real `LivingEntity.knockback` calls across directions, random seeds, velocities, grounded states, strengths and resistances, including synchronization flags.
- 216 real input-vector rotations, 42 friction calculations and 60 acceleration calculations, preserving Java float rounding and the actual sine lookup table.
- 270 actual entity bounding boxes across 90 mapped species and three positions. Exported dimensions retain their original float values widened to doubles.
- Block friction/bounce restitution and actual travel-method ownership/update intervals for the mapped species.

These primitive fixtures are regenerated by `tools/update_reference.py` through `ExportMobPhysics.java`. The exporter uses isolated entity instances to call the actual methods; those calls alone do not prove full entity lifecycle or AI behavior.

## Actual world trajectories

`reference/26.3/mob-motion-trajectories.json` records a normal, AI-enabled Giant in an actual official server. Giants have no navigation goals, so the actor exercises living-entity movement without a wandering controller. Setting `NoAI` would skip relevant travel and is deliberately avoided. The recorder freezes the world and advances exactly one tick, then reads `Pos`, `Motion` and `OnGround` through console data queries while frozen. Every position and velocity is stored as its exact IEEE-754 double bits.

There are six fixtures with 24 ticks each: resting stone, a stone jump, a full stone wall, a bottom slab, ice drag and slime bounces. Each case gets an empty fixture platform; killed actors complete their 20-tick removal before the next actor is created. The observer is outside contact range. The PHP replay uses separate SQLite-backed World instances with matching blocks and compares all six double components plus the ground flag on every tick: 1,008 exact checks. The primitive suite adds 11,035 checks.

Run the native checks with:

```sh
php tests/mob-physics-unit.php
php tests/mob-motion-unit.php
```

After accepting the Minecraft EULA for reference testing, capture a fresh official run without overwriting existing evidence:

```sh
python3 tools/parity/mob_motion.py \
  --jar tools/.cache/26.3/server.jar \
  --java-home /path/to/jdk25 \
  --eula-file /path/to/accepted/eula.txt \
  --output tools/.cache/motion-fresh \
  --compare reference/26.3/mob-motion-trajectories.json
python3 tools/parity/verify.py tools/.cache/motion-fresh/packets.json --java-home /path/to/jdk25
```

The recorder checks the pinned JAR checksum, records raw TCP traffic and leaves partial evidence on failure. Independent official packet codecs decoded 2,897 packets from the captured six-case baseline. The EULA-gated movement CI job repeats the actual world capture, compares every stored bit and independently decodes its packets.

## Remaining scope

The six controlled cases prove ordinary static-block trajectories in those conditions. They do not establish full movement parity for every block shape, support selection at mixed-block edges, world borders, entity pushing, climbing, fluids, passengers, effects, no-gravity states, flying/swimming controllers, special entity bounciness or all species. Supporting-block selection and block effects need broader actual-world fixtures before integration is treated as complete. Navigation input, attack knockback application, shared per-entity randomness, tracked-client velocity and tick frequency still need runtime integration and network parity tests. No broad movement, damage or collision issue is closed by this foundation.
