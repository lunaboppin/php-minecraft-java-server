# Mob movement reference and integration

The native movement work is tracked in #86, with damage/knockback in #87 and shared collision/navigation in #21/#35. The modules in this change establish verified movement arithmetic and a replayable world test. The ordinary ground/air coordinator now uses the verified travel kernel once per server tick. Default melee knockback feeds that velocity, and tracking sends nonzero motion during pairing and position updates. Navigation goals, fluids and special species travel remain incomplete.

`World/EntityPhysics.php` contains shared float/double arithmetic, knockback and input rotation. `World/AirTravel.php` integrates one ordinary ground/air tick against actual World block state. `World/Collision.php` separates static voxel clipping and candidate-height stepping. `Protocol/LowPrecisionVector.php` implements the protocol-777 LpVec3 format used by entity motion; it is not the older three-short velocity format. Keeping these responsibilities separate lets controllers and network tracking use the same verified physics later.

The pinned Java 26.3 server JAR supplies:

- 581 low-precision vector boundary/random cases, including full motion packet bytes, decoded doubles, saturation, NaN and infinities.
- 1,440 real `LivingEntity.knockback` calls across directions, random seeds, velocities, grounded states, strengths and resistances, including synchronization flags.
- 216 real input-vector rotations, 42 friction calculations and 60 acceleration calculations, preserving Java float rounding and the actual sine lookup table.
- 270 actual entity bounding boxes across 90 mapped species and three positions. Exported dimensions retain their original float values widened to doubles.
- Block friction/bounce restitution and actual travel-method ownership/update intervals for the mapped species.

These primitive fixtures are regenerated by `tools/update_reference.py` through `ExportMobPhysics.java`. The exporter uses isolated entity instances to call the actual methods; those calls alone do not prove full entity lifecycle or AI behavior.

## Actual world trajectories

`reference/26.3/mob-motion-trajectories.json` records a normal, AI-enabled Giant in an actual official server. Giants have no navigation goals, so the actor exercises living-entity movement without a wandering controller. Setting `NoAI` would skip relevant travel and is deliberately avoided. The recorder freezes the world and advances exactly one tick, then reads `Pos`, `Motion` and `OnGround` through console data queries while frozen. Every position and velocity is stored as its exact IEEE-754 double bits.

There are six fixtures with 24 ticks each: resting stone, a stone jump, a full stone wall, a bottom slab, ice drag and slime bounces. Each case gets an empty fixture platform; killed actors complete their 20-tick removal before the next actor is created. The observer is outside contact range. The PHP replay uses separate SQLite-backed World instances with matching blocks and compares all six double components plus the ground flag on every tick: 1,008 exact checks. The primitive suite adds 12,197 checks, including full velocity-bearing spawn and teleport packet bytes.

Run the native checks with:

```sh
php tests/mob-physics-unit.php
php tests/mob-motion-unit.php
```

After accepting the Minecraft EULA for reference testing, capture a fresh official run without overwriting existing evidence:

python3 tools/parity/verify.py tools/.cache/motion-fresh/packets.json --java-home /path/to/jdk25

The recorder checks the pinned JAR checksum, records raw TCP traffic and leaves partial evidence on failure. Independent official packet codecs decoded 2,897 packets from the captured six-case baseline. The EULA-gated movement CI job repeats the actual world capture, compares every stored bit and independently decodes its packets.

## Remaining scope

The six controlled cases prove ordinary static-block trajectories in those conditions. They do not establish full movement parity for every block shape, support selection at mixed-block edges, world borders, entity pushing, climbing, fluids, passengers, effects, no-gravity states, flying/swimming controllers, special entity bounciness or all species. Supporting-block selection and block effects need broader actual-world fixtures before integration is treated as complete. The target chooser is still the previous simple wander logic, while the physics and entity-local tracking counters run at 20 Hz for the supported ordinary-travel profiles. Flying, swimming, fluid and custom-travel paths retain their previous fallback behavior. Hurt-window default impulses use a shared per-entity random stream with voices. Base knockback is applied only for a new hurt window; stronger hits inside the existing window do not repeat it. Sprint/enchantment knockback, death motion, navigation and full tracking/interpolation parity remain incomplete. No broad movement, damage or collision issue is closed by this foundation.

## Live network checks

`tests/mob-knockback.py` joins two actual TCP clients, attacks a stationary goal-free Giant and compares both clients' complete compressed velocity-update sequences and the mob's exact settled position/velocity/ground state against the official server. Two isolated comparison runs passed; official codecs decoded all 565 packets from the first passing run. The native test also runs in the complete suite, and the EULA-gated movement job compares both servers. The initial impulse alone was insufficient: Java sends both dirty-movement and hurt-velocity updates, then subsequent thresholded updates at the entity tracking interval. The tracker now preserves those separate flags and entity-local counters.

These controlled comparisons establish default ordinary melee motion in this fixture, not every tracking phase, mob attack, navigation controller or special species behavior. #86/#87/#13 remain open.

The [ordinary movement tracker](ENTITY-TRACKING.md) now supplies native relative/stepped position updates, forced synchronization and cached pairing state for this path. Its own actual-Java frame and wire comparisons supplement the physics evidence above.

A subsequent CI capture exposed the missing player/mob pushing path: a late observer spawned at `(0.5, 64, 2.5)` beside the moving Giant, and Java produced additional diagonal impulses and a different settled position. The retained movement artifact records both complete outcomes. [Issue #105](https://github.com/lunaboppin/php-minecraft-java-server/issues/105) tracks deterministic overlap/non-overlap comparisons and the native pushing implementation. Passing isolated travel checks does not satisfy that collision requirement; the failed case must not be discarded by rerunning until the spawn happens elsewhere.

The [entity pushing modules and controlled-world evidence](ENTITY-PUSHING.md) now establish shared arithmetic, ordered queries and 96 actual-world ticks. Live entity integration and species/player lifecycle remain unfinished; #105 stays open.
